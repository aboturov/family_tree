# Правила репозитория

Репозиторий публичный, а дерево в нём — реальной семьи. Всё, что попадает в git и на GitHub,
видно всем и остаётся в истории навсегда. Поэтому в коде, тестах, комментариях, документации,
сообщениях коммитов, названиях веток и описаниях PR — только вымышленные данные.

## Что нельзя писать

- Реальные имена, фамилии, отчества и прозвища людей из дерева — ни полностью, ни частично.
  Родство без имён («у бабушки два брака») — можно, если по нему нельзя узнать конкретную семью.
- Точные даты рождения, смерти, браков и других событий из реального дерева.
- Реальные места, связанные с семьёй: города, сёла, адреса.
- Id записей из реальной базы и выгрузки (`I7`, `F14`, номера людей и семей).
- Логины и роли реальных пользователей («мама — редактор»).
- Свою инфраструктуру: домены, IP, порты и пути на сервере, имена других сервисов на нём,
  личную почту, пути домашнего каталога.
- Реальный GEDCOM, базу, фото и скриншоты с реальными людьми — ни целиком, ни фрагментами.

## Чем заменять

- Люди: обычные вымышленные ФИО — Иванов Пётр Сергеевич, Орлова (Соколова) Анна Петровна.
- Даты: придуманные, но с теми же свойствами, что нужны тесту (день рождения уже прошёл,
  брак раньше рождения ребёнка и т. п.).
- Места: Тверская область, деревня Примерово.
- Логины в тестах и примерах: `anna`, `olga`, `max`.
- Домен: `tree.example.com`; образ: `ghcr.io/<владелец>/<репозиторий>`.

Разрабатывать, отлаживать и снимать скриншоты — на демо-дереве (`npm run demo`,
`examples/demo.ged`), а не на копии настоящей базы. Не хватает случая — добавить его в демо.

Если случай из реального дерева нужен для теста раскладки — только номерами людей и
словами «трудный случай», без «как у нас» и имён.

## Проверка перед коммитом

Хуки в `.githooks/` сверяют добавленные строки, имена файлов и сообщение коммита с личным
списком слов. Список лежит вне репозитория — `~/.config/family-tree/denylist`, формат — в
`.githooks/denylist.example`. Без списка хуки ничего не проверяют. Включить в клоне:

```bash
git config core.hooksPath .githooks
```

Хуки проверяют и автора коммита: для git в этом репозитории — почта вида
`<id>+<логин>@users.noreply.github.com`, а не личная.

В клоне, где остались ветки с историей до публикации, `pre-push` не даёт их запушить: он
пропускает только потомков первого публичного коммита, если тот указан в
`git config familytree.root <sha>`.

Описания PR и комментарии на GitHub хуки не видят — их проверять глазами по тем же правилам.
